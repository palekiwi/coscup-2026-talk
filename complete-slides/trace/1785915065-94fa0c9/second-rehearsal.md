## Audience feedback

1. Syntax highlighting in code snippets has very low contrast which makes it
   hard to read. Bigger font size would probably help too but hopefully the
   projector screen will be big enough (I will confirm on the first day of the
   conference as my talk is on the second day) because we don't have much margin
   left on our slides. There is already quite a lot of text which should better
   stay for listeners with poorer English listening comprehension.
   We must fix this by finding a better theme for the syntax highlighter.
   Create a TODO.

2. Some suggested adding a pre-recorded demo which would show and prove that
   this actually work. We have considered this idea and originally rejected with
   an argument that the audience should trust the speaker but perhaps a real
   demonstration of the `nix develop` command that leads to some meaningful outcome
   would help. We can reconsider this and discuss properly - create a TODO. The
   audience suggested that if we don't do a demo then we should announce it at the
   beginning of the talk to be transparent.
   It seems that my audience for this rehearsal were looking forward to some kind
   of a demo and they didn't get it.

## My impressions

I think the talk is coherent albeit it does feel dense, there is a lot of
information and I feel I need to rush it a bit and introduce some ideas in a
"rapid fire" succession. I suppose that is OK because we want to make the
audience curious and excited about the topic rather then teach it in depth
(which is impossible in 30mins) and we don't know which idea could resonate with
a particular listener more. The fact is that Nix is a low-level tool and such
tools give more power and open up more possibilities for creative and flexible
problem solving.
